# WaslPay 2.3.6 — idempotent household-message rendering

Revision: Wednesday, 23 September 2026 (Asia/Shanghai).
Baseline checked before editing: `main` commit `1a3bc3273bc6e38238aad60fcb3595241abfd94c`, WaslPay 2.3.5.

## Fixed
- Fix a UI-performance defect in the 2.3.5 household-message enhancer. The script observed character-data mutations while also unconditionally rewriting the same household-summary text. That combination could repeatedly wake the MutationObserver after the enhancer's own writes, causing needless render work while the message center was open.
- Make text and class writes idempotent: unchanged values are no longer written again.
- Narrow the household-message MutationObserver to DOM insertions/removals (`childList` + `subtree`) instead of observing character-data changes generated by the enhancer itself. Click and storage-event refresh hooks remain in place.
- Preserve all 2.3.5 household-budget snapshot validation, 20% warning behavior, exhausted-budget wording, and receipt-history integrity.
- Update the visible preview version, in-app “What’s new?” note, and PWA shell to 2.3.6. All changes are confined to `waslpay/`.
